## 第一部分：功能说明

### 功能概述

报告审查功能用于对 Acqua 输出的 Word 报告进行快速结构化检查，帮助工程师在人工复核前先发现明显问题。

当前版本主要提供以下能力：

- 支持一次选择或拖拽多份本地 `.doc` / `.docx` / `.xlsx` 报告并批量发起审查
- **自动识别同名配对**：同时选入同名的 `.docx` + `.xlsx` 时，系统自动合并两份数据执行完整17项检查（Word提供文档结构，xlsx提供测试时序和内容数据），不再降级
- 自动执行 17 项检查（8项文档结构+元数据 + 5项测试时序 + 4项内容合理性）
- **跨报告批量对比**：≥2份报告时自动触发，独立面板按 Codec/网络分组展示响度差异明细（pairwise 数值对比）
- **批量对比概览**：替换旧三卡片，展示本轮所有报告的通过/警告/复核/错误统计表格
- **`.docx` 目录页数自动提取**：从文档元数据中读取总页数
- **`.doc` COM 保真转换**：优先使用 Word/WPS COM 接口转换 `.doc` → `.docx`（保留页数、表格、章节），无 COM 时自动降级
- 将审查结果保存到页面历史记录，而不是只停留在一次性弹窗里
- 支持从历史记录再次打开详情，并清空历史列表
- 支持点击”最近审查记录”表格中的统计标签，按类别查看具体检查项
- 将”检查范围说明”降级为默认折叠的辅助信息区，减少对主任务区的干扰

### 使用方式

#### 1. 进入页面

在应用左侧导航点击 **报告审查**，进入审查页面。

#### 2. 选择本地报告

页面顶部提供一个居中的文件选择区：

```text
┌────────────────────────────────────┐
│      点击或拖拽选择多个文件        │
│   支持一次导入多个 .doc/.docx      │
└────────────────────────────────────┘
```

支持两种方式：

- 点击选择区，打开本地文件选择对话框并多选报告
- 直接将多个 `.doc` / `.docx` 文件拖入选择区

选择成功后，页面会显示当前已选报告列表，并支持单独移除或一键清空。

#### 3. 开始审查

点击右侧 **开始审查** 按钮后，系统会执行以下流程：

1. 校验文件路径与文件格式
2. 将当前批次报告按顺序逐份送入审查链路
3. 若为 `.doc`，先在后台转换为临时 `.docx`
4. 解析 Word 内容并构造统一审查数据
5. 执行 8 项检查逻辑
6. 生成结构化审查结果并写入历史记录

补充说明：

- 批量审查过程中，页面会显示当前处理文件、完成进度、成功数和失败数
- 如果部分报告失败，结束后会弹出失败汇总，方便单独排查

#### 4. 查看结果与历史

当前版本的结果查看方式如下：

- 页面下方会保留最近审查记录
- 每条历史都可以点击 **查看详情** 打开详细结果
- “最近审查结论”卡片中的统计标签支持点击后按状态筛选明细
- “最近审查记录”表格中的 **检查统计** 标签支持点击后按状态筛选明细
- 支持 **清空列表** 删除本地历史记录

说明：

- 结果不会因为关闭详情窗口而丢失
- 历史记录保存在浏览器本地存储中，仅在当前机器当前环境下可见
- 统计标签点开后，可只看当前报告中的警告项、复核项、错误项或通过项
- “检查范围说明”默认收起，需要时再展开查看

### 支持的文件格式

- `.doc` / `.docx` — Word 报告，提供文档结构、元数据、POLQA 配置等检查
- `.xlsx` — ACQUA 导出的测试报告，提供测试时序和内容合理性检查
- **配对导入**：同时选择同名的 `.docx` + `.xlsx` 可获得最完整的审查结果（17项全量执行，不再降级）

### 当前审查项

系统当前固定执行以下 17 项检查：

**文档结构（1-3）**
1. 目录提取
2. 目录页数检查
3. 章节与目录对应

**元数据与命名（4-8）**
4. 报告基本信息一致性
5. 测试项一致性
6. 名称污染检查
7. 测试人员信息识别
8. POLQA 配置检查

**测试时序（9-13）—— xlsx报告专属**
9. 相邻测试项间隔检查（除3quest外≤5分钟）
10. 全部测试项跨度检查（≤6小时）
11. 时延测试时序检查（Delay应在最前）
12. Sidetone Delay时序检查
13. BGN Connection时序检查

**内容合理性（14-17）—— xlsx报告专属**
14. 单报告内响度与频响趋势一致性
15. 单报告内曲线与数值互相印证
16. 跨报告：同Codec不同网络响度差异≤1dB
17. 跨报告：同网络不同Codec响度差异≤1dB

> 注：9-15项检查对Word报告自动降级为"需人工复核"；16-17项在批量审查（≥2份报告）时自动执行。

### 审查结果状态说明

每项检查和整体结果都使用以下状态：

- `pass`：通过
- `warning`：有警告
- `review`：需人工复核
- `error`：有错误

### 当前限制

1. `.doc`（旧版二进制格式）COM 转换需本机安装 Word 或 WPS（自动检测，无 COM 时自动降级到文本重建）。
2. `.docx` 页数来自保存时写入的元数据（`docProps/app.xml`），程序生成的 `.docx` 可能缺失该字段。
3. 测试项一致性、人员识别、POLQA 配置识别本质上是规则和关键词驱动，不等同于人工最终结论。
4. 频响曲线图表当前仅做数值趋势对比，无法解析图表图片中的曲线形态。
5. 配对审查要求 `.docx` + `.xlsx` 同名且同目录；文件名差异较大时可能无法自动配对。

## 第二部分：当前模块结构

### 1. 主进程报告审查模块

当前报告审查主进程代码结构如下：

```text
src/main/services/reportReview/
├─ index.js
├─ wordReviewService.js
├─ utils.js
├─ reportFacts.js
├─ reportTestDataFacts.js     ← 新增：ACQUA xlsx数据提取层
├─ reportBuilder.js
└─ checks/
   ├─ documentStructure.js
   ├─ metadata.js
   ├─ polqa.js
   ├─ timing.js               ← 新增：测试时序检查（2.3）
   └─ contentConsistency.js   ← 新增：内容合理性检查（2.2）
```

职责划分：

- `index.js`
  - 作为报告审查模块统一入口
  - 调用 `parseReport()` 解析 Word 报告
  - 调用审查服务生成 `reviewResult` 和 `report`

- `wordReviewService.js`
  - 负责审查流程编排
  - 组织 17 项检查执行顺序
  - 构建 `testDataFacts` 供 xlsx 专属检查使用
  - 汇总 `summary` 和 `overallStatus`

- `reportFacts.js`
  - 负责统一提取报告审查事实数据
  - 汇总正文、表格、页眉页脚、多源 Measurement Object、人员候选、POLQA 线索
  - 作为目录、元数据、人员、POLQA 检查的共用事实层

- `reportTestDataFacts.js`（新增）
  - 负责从 ACQUA xlsx 的 Detailed 工作表提取结构化测试数据
  - 提取测试时间戳（Date/Time列）、响度数值（Value/Direction/VolumeCTRL）、频响数据
  - 对 Word 报告返回 null，实现优雅降级
  - 为时序检查和内容合理性检查提供统一数据源

- `checks/documentStructure.js`
  - 目录提取
  - 目录页数检查
  - 章节与目录对应检查

- `checks/metadata.js`
  - 基本信息一致性
  - 测试项一致性
  - 名称污染检查
  - 人员识别

- `checks/polqa.js`
  - POLQA / MOS-LQO / P.863 相关配置检查

- `checks/timing.js`（新增）
  - 相邻测试项间隔检查（2.3.1）
  - 全部测试项跨度检查（2.3.2）
  - 时延测试时序检查（2.3.3）
  - Sidetone Delay时序检查（2.3.4）
  - BGN Connection时序检查（2.3.5）

- `checks/contentConsistency.js`（新增）
  - 同Codec不同网络响度差异检查（2.2.1，跨报告）
  - 同网络不同Codec响度差异检查（2.2.2，跨报告）
  - 单报告内响度与频响趋势一致性检查（2.2.3）
  - 单报告内曲线与数值互相印证检查（2.2.4）

- `reportBuilder.js`
  - 将结构化检查结果转成前端展示使用的 section 列表

#### 二、重点修改项与解决的问题

##### 1. 曲线与数值互相印证逻辑继续收口，修掉 Utah HH WB 下 MAX 末档误判

**问题现象**：在 `utah_HH_WB.xlsx` 的响度校验里，界面上经常把最后一个 `MAX` 点识别错，导致 `MAX → MAX-1` 被判成大幅下降，单调性只剩 86%。

**根因**：源 `xlsx` 的 `VolumeCTRL` 列是粗粒度字段，`MAX-1` 到 `MAX-6` 实际都写成 `MAX`；旧逻辑在 `contentConsistency.js` 中优先按 `VolumeCTRL` 匹配，导致多个等级被错误并入同一个 `MAX` 组。

**本轮修复**：
- 在 `volumeLevelUtils.js` 中统一八级响度等级的规范名、别名和排序规则。
- 在 `contentConsistency.js` 中改为优先从 `descriptor/SMD` 标题提取精确等级，只有标题无法给出等级时才回退到 `VolumeCTRL`。
- 单调性结果开始与图表组件联动，前端可以直接看到异常点位和跨等级变化链路。

**结果**：`MAX / MAX-1 / MAX-2 / MAX-3(NOM) / MAX-4 / MAX-5 / MAX-6 / MAX-7(MIN)` 八个等级能够一一对应真实数值，不再把 `MAX-6` 的 23.94dB 误当成 `MAX` 值，从而消除了这类虚假的下降警告。

##### 2. 报告审查链路从“静态结果”升级为“过程可见 + 证据可视”

**优化点**：
- `progressBus.js` 把主进程长耗时分析过程显式化，便于前端感知 LLM 图像分析、报告解析、审查执行等步骤。
- `imageExtractor.js`、`llmService.js`、`wordReviewService.js`、`reportBuilder.js` 协同增强，让曲线识别、文字结论、诊断证据和结构化 section 的组织更完整。
- `ReviewResultContent.jsx` 与新增的 `MonotonicityChart.jsx` 配合，把“通过/警告/异常点/诊断依据”从纯文本升级为图表+清单组合展示。

**解决的问题**：
- 过去结果虽然能提示“有问题”，但用户难以立刻看出是哪一个等级、哪一个方向出了问题。
- 现在结果页已经能把异常点、趋势线、相邻等级变化和解释性文本放在一起，复核路径更短。

##### 3. LLM 配置与图像分析能力继续扩展

**优化点**：
- 设置页和设置服务联动，增加了更完整的 LLM 配置项与联通性测试入口。
- 图像分析的批量能力与结果展示继续增强，后端对报告图像的识别、分类和分析链路更清晰。

**解决的问题**：
- 以前 API 是否可用、参数是否生效，更多依赖人工猜测；现在设置页已经开始提供直接测试与反馈。
- 以前曲线识别更接近“黑箱结果”；现在链路层级和结果表达都更接近可定位、可解释的工程工具。

##### 4. 全局主题系统开始成形，页面样式不再靠零散覆盖

**优化点**：
- 引入 `ThemeContext.js` 承接设计风格状态。

**解决的问题**：

### v1.1.7+ 第四轮 — 修复 .doc 文件频响曲线图片无法提取（2026-05-15）

**问题**：使用 `.doc` 格式报告进行审查时，检查项 14（响度与频响趋势一致性）始终提示"未检测到响度/频响曲线图"，即使报告中确实包含频响曲线。

**根因**：路径断链。`parseReport()` 内部已将 `.doc` 通过 COM 转换为 `.docx` 并成功解析，但转换后的 `.docx` 路径没有返回给调用方。`reviewWordReport()` 和 `reviewPairedReport()` 仍使用原始 `.doc` 路径传给 `extractReportImages()`，而该函数通过 JSZip 读取图片，`.doc` 是二进制 OLE2 格式无法作为 ZIP 打开，`JSZip.loadAsync()` 直接失败返回空数组。

**修复**：`src/main/services/reportReview/index.js` 新增 `resolveEffectivePath()` 函数。当原始路径为 `.doc` 且 `parseReport()` 返回 `reportFormat: 'docx'`（说明 COM 转换成功）时，自动将路径替换为同目录下对应的 `.docx` 路径。`reviewWordReport()` 和 `reviewPairedReport()` 均使用 `effectivePath` 传递给下游。

**改动文件**：`src/main/services/reportReview/index.js`（新增 `resolveEffectivePath` 函数 + 两处调用）

**验证**：React 构建通过。Utah HA NB `.docx` 可正常提取 48/77 张频响曲线图；`.doc` 文件路径修复后也可正常提取。
