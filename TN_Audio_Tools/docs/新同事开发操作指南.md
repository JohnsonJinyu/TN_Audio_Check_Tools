# 新同事开发操作指南

本指南写给第一次参与 TN Audio Toolkit 项目的开发同事。每一步都尽量详细，跟着做就行。遇到问题先翻到最后的「常见问题」部分。

---

## 0. 开始之前（重要！必读）

### 你需要在本机安装这些软件

| 软件 | 下载地址 | 备注 |
|------|----------|------|
| **Node.js 18+** | https://nodejs.org | 选 LTS 版本，一路下一步即可 |
| **Git** | https://git-scm.com/download/win | 安装时全部默认选项即可 |
| **Cursor** 或 **VS Code** | https://cursor.com 或 https://code.visualstudio.com | 推荐 Cursor，AI 辅助写代码 |

安装完成后，打开一个终端（PowerShell 或 CMD），验证一下：

```powershell
node --version    # 应显示 v18.x.x 或更高
npm --version     # 应显示 9.x.x 或更高
git --version     # 应显示 git version 2.x.x
```

### 你不需要配 SSH（直接用 HTTPS）

新手推荐走 HTTPS，不需要生成 SSH Key，不需要我这边配置公钥。直接用 Gitee 账号密码或私人令牌即可。

> 如果你已经会 SSH，想走 SSH 方式，见最后一节「附录：SSH 方式（可选）」。

## 1. 克隆项目到本地

### 1.1 打开终端

在你要放代码的文件夹（比如桌面）右键 → "在终端中打开"（Windows 11），或者打开 CMD/PowerShell 后 `cd` 到目标目录。

### 1.2 克隆

```powershell
git clone https://gitee.com/lingyu_mayun/TN_Audio_Check_Tools.git
```

克隆完成后会多出一个 `TN_Audio_Check_Tools` 文件夹，里面就是项目代码。

### 1.3 进入项目目录

```powershell
cd TN_Audio_Check_Tools\TN_Audio_Tools
```

### 1.4 切换到开发分支

你刚克隆下来时，默认在 `master` 分支。**日常开发不在 master 上做**，要先切到 `dev`：

```powershell
git switch dev
```

> **记住**：`master` = 稳定发布版，`dev` = 日常开发版。你所有工作基于 `dev`。

### 1.5 安装依赖

```powershell
npm install
```

这一步会下载所有依赖包，大约需要 2-5 分钟，取决于网络。

### 1.6 启动开发环境

```powershell
npm start
```

这会同时启动 React 前端和 Electron 桌面窗口。看到应用窗口弹出来，说明环境 OK。

## 2. 日常开发流程（每次开发前必看）

### 核心规则（记住这四条就够了）

1. **永远不要在 `dev` 或 `master` 分支上直接改代码**
2. **每做一个新功能 / 修一个 Bug，都从 `dev` 新建一个分支**
3. **分支命名：`feature/功能名` 或 `fix/修复名`**
4. **做完后合并回 `dev`**

### 2.1 开始新需求前

```powershell
# 1. 切到 dev
git switch dev

# 2. 拉取最新的 dev（因为别人可能更新了）
git pull origin dev

# 3. 从 dev 创建你的功能分支
git switch -c feature/你的功能名
```

分支命名示例：
- `feature/report-review-optimization`（报告审查优化）
- `feature/add-batch-export`（新增批量导出）
- `fix/settings-crash`（修复设置页崩溃）

### 2.2 在功能分支上开发

正常写代码。写完之后保存文件，然后提交：

```powershell
# 查看你改了什么
git status

# 添加所有改动（或用 git add 具体文件名）
git add .

# 提交（写清楚你做了什么）
git commit -m "feat: 新增批量导出功能"
```

提交信息建议格式：
- `feat: xxx` — 新功能
- `fix: xxx` — 修复 Bug
- `refactor: xxx` — 代码重构
- `docs: xxx` — 文档更新

### 2.3 推送你的分支

```powershell
git push origin feature/你的功能名
```

> 推送前会提示你输入 Gitee 账号和密码（或私人令牌）。如果嫌每次输入麻烦，可以在 Gitee 上生成私人令牌代替密码，或者配置 SSH（见附录）。

### 2.4 如果开发周期较长，中间同步一下 dev

如果功能做了好几天，期间 `dev` 可能被别人更新过，你需要同步一下：

```powershell
# 1. 先切到 dev 拉取最新
git switch dev
git pull origin dev

# 2. 切回你的功能分支
git switch feature/你的功能名

# 3. 把 dev 的更新合并进来
git merge dev
```

## 4. 分支管理一览

```
master ──────────────────────────────── ● (稳定发布)
   │                                     │
   └── dev ────────────────────────── ● (日常开发基线)
          │                            │
          ├── feature/xxx ── ● ── ● ── ┘ (功能分支，完成后合回 dev)
          │
          ├── feature/yyy ── ● ── ● ── ┘
          │
          └── fix/zzz ────── ● ──────── ┘
```

**你只做三件事**：
1. 从 `dev` 拉新分支
2. 在自己的分支上开发和提交
3. 完成后告诉我（或自己合并到 `dev`）

## 5. 提交代码前自检清单

每次 `git commit` 之前确认：

- [ ] 你的代码能跑起来（`npm start` 不报错）
- [ ] 你在正确的分支上（`git branch` 确认，不是 `dev` 或 `master`）
- [ ] 没有把 `node_modules/`、`dist/`、`.env` 等不该提交的文件加进去
- [ ] commit message 写清楚了改动内容
- [ ] 只改了你应该改的文件，没有误改其他文件

## 6. 我需要你做什么（仓库管理侧）

新手走 HTTPS 不需要你这边额外配置。只需要确保：

1. **仓库是公开的**（当前 Gitee 仓库 `lingyu_mayun/TN_Audio_Check_Tools` 需确认权限为公开或内部可见）
2. 如果仓库是私有的，在 Gitee → 仓库 → 管理 → 仓库成员管理 → 添加同事的 Gitee 账号为「开发者」

如果是 SSH 方式，才需要你把同事的公钥添加到 Gitee（见附录）。

## 7. 常见问题

### Q: `npm install` 报错或很慢？
A: 先试试换成国内镜像：
```powershell
npm config set registry https://registry.npmmirror.com
npm install
```

### Q: 推送时提示 "Permission denied"？
A: 两种可能：
1. 你没有仓库的推送权限 → 找我（仓库管理员）添加你为 Gitee 仓库成员
2. 账号密码错了 → 检查 Gitee 账号是否能正常登录 https://gitee.com

### Q: `git push` 提示输入用户名密码，输什么？
A: 用户名是 Gitee 注册时用的邮箱或用户名。密码推荐用 **私人令牌**：
1. 登录 Gitee → 右上角头像 → 设置 → 私人令牌
2. 生成新令牌，权限勾选 `projects`
3. 复制令牌，粘贴到密码输入处

### Q: 我改错了文件想撤销？
A:
```powershell
# 撤销单个文件的修改（回到上次提交的状态）
git checkout -- 文件名

# 撤销所有未提交的修改
git checkout -- .
```

### Q: 我在错误的分支上提交了怎么办？
A: 先别慌，找我帮你处理。通常用 `git cherry-pick` 或 `git reset` 可以解决。

### Q: `npm start` 启动后窗口闪退？
A:
```powershell
# 先单独启动 React 看看报什么错
npm run react-start
```

### Q: 我不知道自己当前在哪个分支？
A:
```powershell
git branch
```
带 `*` 号的就是当前分支。

## 附录：SSH 方式（可选，新手可跳过）

如果你不想每次 push 都输密码，可以配置 SSH。

### 同事侧（你自己做）

1. 生成 SSH Key（如果还没有）：
```powershell
ssh-keygen -t ed25519 -C "你的邮箱@example.com"
```
一路回车即可。生成的文件在 `C:\Users\你的用户名\.ssh\id_ed25519.pub`。

2. 把 `id_ed25519.pub` 文件里的内容发给我（仓库管理员）。

3. 然后在本机配置 SSH remote：
```powershell
cd TN_Audio_Check_Tools\TN_Audio_Tools
git remote set-url origin git@gitee.com:lingyu_mayun/TN_Audio_Check_Tools.git
```

### 管理员侧（我做）

收到同事的公钥后：
1. 登录 Gitee → 右上角头像 → 设置 → SSH 公钥
2. 把同事的公钥粘贴进去，标题写同事名字
3. 保存

或者直接在仓库层级添加（推荐）：
1. Gitee → 仓库 → 管理 → 部署公钥管理 → 添加公钥
2. 粘贴同事的公钥，勾选「授予写入权限」
